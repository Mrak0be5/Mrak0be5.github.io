# Kraken / Octopus RPG

Статический адаптивный дашборд на русском языке. Vanilla HTML, CSS, JavaScript, SVG; без зависимостей, сборки, шрифтов с внешних серверов и демонстрационных данных. Тёмная тема по умолчанию, переключатель светлой темы сохраняет настройку в localStorage, если браузер разрешает его использование.

## Файлы

- `index.html` — оболочка, навигация, фильтры, диалог справки.
- `styles.css` — темы, адаптивная сетка, таблицы, графики.
- `app.js` — загрузка снимка, интерфейс, SVG, поиск, сортировка, экспорт.
- `logic.mjs` — чистые расчёты и подготовка CSV; доступен импорт для отдельных тестов.

Файл `data.json` содержит реальный агрегированный отчёт Adjust для Octopus RPG. Сборщик установлен отдельно на основном ПК пользователя; ключ защищён Windows DPAPI и не публикуется. Каталог можно опубликовать в GitHub Pages без сборки. Для локального просмотра нужен HTTP-сервер: ES modules и fetch не рассчитаны на открытие через `file://`.

Интерфейс делает только `fetch('./data.json?cache=' + Date.now())` с `cache: 'no-store'` и таймаутом 20 секунд. Кнопка «Обновить» перечитывает снимок, не запускает сборщик. Автоматический сбор раз в 6 часов выполняется отдельно на ПК; отметка времени показывает именно `generated_at`. Ошибка обновления сохраняет предыдущий снимок с явным предупреждением.

## Контракт данных

Поддерживается `schema_version: 1` со свойствами `app`, `generated_at`, `range`, `currency`, `timezone`, `refresh`, `metrics`, `daily`, `acquisition`, `cohorts`, `events`, `event_rows`, `spend_rows`, `spend`, `warnings`, `availability` описанными ниже. Отсутствующие массивы трактуются как пустые. Неподдерживаемая версия схемы, сетевые ошибки и повреждённый JSON отображаются отдельным состоянием.

Даты строк и границ — календарные `YYYY-MM-DD` в UTC. Числовые метрики должны быть конечными JSON-числами: строки, null и отсутствующие поля считаются неизвестными. Обе границы периода включены. Начальный период — последние 30 дней до вчерашнего дня UTC, независимо от свежести снимка. Сегодня помечается как неполный день. Выход за `range` отмечается явно; средний DAU за неполностью покрытый период недоступен. Максимум пользовательского периода — 3660 дней для защиты интерфейса от чрезмерного числа точек.

`availability.daily`, `.acquisition`, `.cohorts`, `.spend`, `.events` авторитетны. Если списка или идентификатора нет, значение — «—», даже когда числовое поле присутствует. Отсутствие одной числовой ячейки делает её агрегат неизвестным: неполная сумма не выдаётся за полный результат. Пустой набор строк также не превращается в ноль. Ноль отображается только для известного числового нуля либо пропущенного дня внутри заявленного покрытия непустого набора для доступной метрики.

Предположение о покрытии: `range` описывает непрерывные дни, за которые выгрузка завершена. Внутри этого диапазона отсутствующий день непустого выбранного набора трактуется как день без активности в графиках и таблице по дням. Если сборщик пропустил день из-за ошибки, он должен явно сигнализировать это через `warnings` и не заявлять полное покрытие. Неизвестные поля существующих строк всегда остаются «—».

## Расчёты

- Без фильтра сети/страны обзор использует `daily`, с такими фильтрами — `acquisition`. Платформа действует во всех разделах. Страна сопоставляется по `country_code`, с резервным `country`.
- DAU доступен только из `daily`. KPI показывает сумму DAU по дням и ОС / число календарных дней периода, включая нулевые дни. Таблица и график показывают DAU одного дня. DAU нельзя трактовать как уникальную аудиторию всего периода.
- `revenue` — IAP активности, `ad_revenue` — рекламный доход активности, `revenue_total` — их сумма. Если общий доход не записан, он выводится из двух составляющих только при доступности всех трёх идентификаторов и числовых значениях составляющих.
- Расходы — метрика `network_cost`, режим network, из отдельного набора `spend_rows`. У одного пакета две записи Adjust: Octopus RPG (`xrf4y61ie6tc`) и TEST1 (`qrhws2aui134`). Расходы фактически приходят в TEST1. Сборщик проверяет `store_id` обеих записей и берёт только затраты и установки сети; игровые показатели получает исключительно из Octopus RPG. Для одинакового дня, платформы, партнёра, кампании и страны записи не складываются повторно; приоритет имеет ненулевой расход основной записи. CPI Adjust = сумма расходов сетей / платные установки из `acquisition`. CPI сети = сумма расходов / `network_installs` из `spend_rows`. Эти показатели могут различаться из-за разных моделей атрибуции сети и Adjust. Organic, Unknown Devices, unknown и unattributed исключены из платного трафика. При нулевом знаменателе — «—». Если Adjust возвращает нулевые затраты за весь снимок при наличии платных установок, расходы не подтверждены; причина указана в карточках, предупреждении и `spend`.
- «Доход / расходы» — отношение общего дохода активности к расходам за выбранный период. Это множитель, не когортный ROAS. Когортный ROAS не рассчитывается, поскольку отдельный контракт соответствия когорт и расходов не задан.
- Сравнение KPI — предыдущий период той же календарной длины с теми же фильтрами. Требуется покрытие обоих периодов и известные значения; при нулевом предыдущем значении процент не рассчитывается. При включённом сегодняшнем дне сравнение скрыто. Для расходов и CPI снижение отмечается положительным цветом.
- Удержание D1/3/7/14/30 = сумма `retained_users_dN` / сумма `cohort_size_dN`. Весами служат соответствующие размеры зрелых когорт, а не число установок и не среднее процентов. Группировка по дню установки, со всеми фильтрами.
- Зрелость консервативная: дата установки + N + 1 должна быть не позже вчерашнего дня относительно `generated_at` UTC. Adjust определяет D0 как первые 24 часа, D1 как следующие 24 часа; дополнительная граница гарантирует завершение окна даже для последней установки в дату когорты. При неизвестной дате снимка значения когорт скрыты.
- Когортный `revenue_total_dN` накопительный. D0 тоже показывается после завершения дня установки.
- События используют `events` для названий и идентификаторов, `event_rows` для сумм, `availability.events` для доступности. Это количество срабатываний, не уникальные пользователи.

## Управление и доступность

Семь разделов доступны по hash-ссылкам, включая отдельные «Кампании» и «Креативы». Фильтры общие. Поиск и сортировка таблиц сохраняются отдельно для каждого раздела; сброс возвращает 30 дней, все измерения, начальные показатели графиков и сортировку. Группировка привлечения — по рекламному партнёру, кампании или стране. Для общего фильтра сети используется `partner_name` с резервным `network`; Facebook, Instagram и Off-Facebook объединены в Facebook, поскольку затраты Meta приходят на уровне партнёра. Переключатель когорт показывает удержание, накопительный доход или показатели на игрока.

SVG-точки доступны с клавиатуры: Tab переводит фокус в график, стрелки переходят между точками, Home/End — к первой/последней, Escape скрывает подсказку. Значения графиков также доступны в таблице «Данные по дням». Таблицы прокручиваются горизонтально и имеют доступные заголовки и состояние сортировки. Диалог справки использует нативный `dialog`, закрывается кнопкой и Escape. Анимация загрузки учитывает reduced motion.

CSV экспортирует текущую таблицу с фильтрами, поиском и сортировкой; в обзоре — данные по дням. Раздел источника экспортирует свойства снимка, размеры наборов и доступность метрик (его свойства не зависят от фильтров). Имя содержит раздел и выбранные даты. Экспорт UTF-8 с BOM, CRLF, кавычки удвоены; потенциальные формулы с `=`, `+`, `-`, `@`, пробельным префиксом или управляющими символами защищены апострофом. Неизвестные значения экспортируются пустыми ячейками; удержание — доля, отношение дохода/расходов — множитель. В интерфейсе весь текст снимка экранируется или вставляется через textContent.

## Проверки

В `logic.mjs` есть небольшая самопроверка дат, равных периодов, неизвестных значений и CSV; она не вызывается интерфейсом и не создаёт данные отчёта. На ПК пользователя из каталога проекта:

```sh
on-remote node --check kraken-dashboard-work/site/app.js
on-remote node --check kraken-dashboard-work/site/logic.mjs
on-remote node --input-type=module -e "import('./kraken-dashboard-work/site/logic.mjs').then(m => console.log(m.selfCheck()))"
```

Сборка не требуется. Браузерные и интеграционные проверки с реальным снимком выполняются отдельно. Никакие ключи, токены или персональные данные игроков публиковать нельзя: содержимое `data.json` общедоступно.

## Обновление

Публичный адрес: https://mrak0be5.github.io/kraken-dashboard/. Планировщик Windows запускает задачу `KrakenDashboard-Adjust-6h` каждые 6 часов под текущим пользователем. ПК должен быть включён, подключён к интернету и пользователь должен быть вошедшим в Windows. После пропущенного запуска включено выполнение при первой возможности. Журнал последнего запуска: `%LOCALAPPDATA%\KrakenDashboard\refresh.log`. Сборщик обновляет только `kraken-dashboard/data.json` через уже настроенный GitHub CLI. При ошибке API прежний опубликованный отчёт сохраняется.

Отчёт охватывает последние 365 дней, включает текущий неполный день и не содержит идентификаторов игроков. Для расходов, не переданных Adjust, показано «—». Поскольку отчёт опубликован в GitHub Pages, агрегаты доступны всем по ссылке.

## Плейтайм и монетизация

На обзоре отдельно показаны затраты сетей, CPI Adjust и CPI сети, доход рекламы, доход IAP, количество событий покупки, ревардеды и все рекламные показы. Покупки — `revenue_events`, это события оплаты, а не число плательщиков. `ad_impressions` включает все форматы и не используется для вычисления ревардедов. Отдельный счётчик rewarded берётся только из события `rewarded_ad_completed`; пока событие отсутствует в Adjust, показатель неизвестен. Это событие должно отправляться один раз после фактического завершения рекламы; выдача подарка без просмотра не учитывается.

Блок «На одного игрока · D0 / D1 / D7» стоит сразу под основными карточками в обзоре и привлечении. Средний плейтайм вычисляется как сумма `time_spent_dN` / сумма `cohort_size_dN` для полностью завершившихся дней когорт. Среднее взвешено по размеру когорты, включает неактивных игроков и относится к конкретному дню после установки, не ко всему накопленному периоду. D0 — первые 24 часа после установки. Время отображается в минутах и секундах, CSV сохраняет исходные секунды.

Реклам на игрока Dn = сумма `ad_impressions_total_in_cohort_dN` / сумма `cohort_size_dN`: все форматы накопительно от установки до дня N. LTV Dn = сумма `all_revenue_total_in_cohort_dN` / тот же размер когорты. Компоненты LTV рекламы и IAP вычисляются из `ad_revenue_total_in_cohort_dN` и `revenue_total_in_cohort_dN`. Используются именно суммы в зрелой когорте, чтобы не делить доход незрелых игроков на размер зрелой когорты. LTV — наблюдаемый накопленный доход на игрока к указанному дню, без прогноза будущих доходов. Для маленьких сумм интерфейс показывает четыре знака после запятой.

«Реклам / активного игрока в сутки» = сумма показов активности / сумма DAU. Это средняя нагрузка на активного игрока за сутки; сумма DAU не выдаётся за уникальную аудиторию всего периода. При фильтрации по сети, стране, кампании или креативу метрика недоступна, поскольку DAU в таком разрезе не выгружается.

Таблица обзора сочетает календарную активность дня и метрики когорты, установленной в этот день; подпись объясняет два значения даты. В таблице привлечения когорты присоединяются по сети, кампании или стране. В выгрузке когорт есть поле `campaign`. В разделе «Когорты» добавлен режим «Плейтайм, реклама и LTV / игрока» для D0/D1/D7.

Общий показатель `time_spent` недоступен этому API-ключу, поэтому для плейтайма используются разрешённые когортные метрики. Для наблюдаемых покупок и дохода отображаются данные, переданные в Adjust; нулевой результат не подтверждает отсутствия покупок в магазине при ненастроенной отправке событий.

## Кампании и креативы

В «Кампаниях» показаны название, сеть и ID кампании. В «Креативах» показаны название объявления, рекламная кампания, группа объявлений и ID объявления, а также расходы, установки Adjust и сети, оба CPI, плейтайм D0/D1/D7, реклама на игрока, LTV, покупки и доходы рекламы и IAP. Эти таблицы доступны также через группировку раздела «Привлечение».

Сборщик получает `campaign_network`, `campaign_id_network`, `adgroup_network`, `adgroup_id_network`, `creative_network` и `creative_id_network` для активности, когорт и расходов. Названия и ID нормализуются в поля `campaign_name`/`campaign_id`, `adgroup_name`/`adgroup_id`, `creative_name`/`creative_id`. При отсутствии сетевого названия используется название атрибуции; суффикс с ID отделяется от имени. Значение `unknown` не выдается за название.

Группировка и сопоставление расходов используют сеть и ID кампании, группы и объявления. Одинаковые названия с разными ID сохраняются отдельными строками. При удалении дубликатов затрат учитывается ID объявления, чтобы не потерять расходы других креативов. Расходы, которым Adjust не назначил креатив, остаются в отдельной строке и не распределяются предположительно.

Общие фильтры кампании и креатива действуют на карточки, графики, таблицы, когорты и CSV. Нажатие на название в таблице выбирает этот объект. Креатив без атрибутированных установок, но с расходами, остается в таблице с нулём установок Adjust; плейтайм и LTV без знаменателя остаются неизвестными. CSV сохраняет названия кампаний, групп объявлений, ID и все показатели текущей таблицы.
