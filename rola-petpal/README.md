# ROLA PetPal — домашняя станция

Статическая страница на GitHub и локальный пульт диагностики на Windows.

На 2026-10-17 робот найден и подтверждён по MAC. Подключён реальный API SD-карты: ёмкость, использованное и свободное место, список дней с записями. Запросы явно привязаны к адресу UGREEN: выбор интерфейса Windows по умолчанию мог отправлять их через Ethernet.

Пульт не управляет движением, камерой, базой и выдачей лакомств. Эти функции не предоставлены подключёнными методами; их работа не заявляется и телеметрия не имитируется.

## Запуск на ПК

`python -m pip install bleak`

`python discover.py` — поиск устройств по MAC через ARP, проверка TCP-сервисов обнаруженных устройств в сети 192.168.1.x и объявлений Bluetooth. Отсутствие открытого HTTP-порта не мешает поиску по MAC. Результат хранится только на ПК в `%LOCALAPPDATA%\RolaDashboard\discovery.json`.

`python start.py` — скрытый запуск пульта http://127.0.0.1:8794/. Кнопка «Повторить поиск» обновляет диагностику. Фоновый сервер слушает только loopback, внешний доступ не разрешён.

Состояние Wi-Fi читается заново при обновлении пульта. Оно показывается отдельно от результата последнего поиска робота: старая запись не означает, что ПК по-прежнему подключён к той же сети.

`python -m unittest test_server test_network_state test_robot_api -v` — проверки доступа, разбора данных API и выбора UGREEN без команд настоящему роботу.

Публичная страница содержит только интерфейс. Для диагностики нужно открыть локальный пульт или импортировать локальный JSON; импорт выполняется в браузере, файл никуда не загружается. Реальные SN, MAC, Wi-Fi, учётные данные и результаты сканирования не публикуются.

## Совместимость

Методы `GET /httpAction/getStorageDetails` и `GET /httpAction/getRecordingDays?tag=0` на порту 9036 проверены непосредственно на ROLA PetPal. Для работы дашборда нужен включённый ПК с локальным компонентом и доступом к сети робота. Публичная страница сама не открывает доступ к домашней сети.
